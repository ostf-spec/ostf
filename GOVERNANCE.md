# Draft governance

OSTF is a public, maintainer-led working draft in the `ostf-spec` GitHub organization. It is not yet governed by a standards body, and publication does not certify implementations. Repository maintainers decide what merges; proposals and their rationale remain visible in issues and pull requests.

For a normative change, open an issue or pull request that identifies the affected `OSTF-` IDs, the ambiguity or use case, compatibility effects and proposed conformance cases. Maintainers review the text, schemas, annexes and fixtures together. Existing requirement IDs are retired rather than reused. A merged pull request records a draft decision, not 1.0 consensus or an assurance claim.

Document revision, wire version and conformance-suite version change independently. The [Core draft](draft/core.md#proposed-areas-schemas-and-claims) defines current claim limits, and [OSTF-023](draft/core.md#proposed-areas-schemas-and-claims) defines the independent implementation and adoption gates for 1.0. Any future transfer to a neutral home requires a separately published governance decision.
